Multi-solution support: All workflows accept a solutions input — "all" deploys every solution in src/solutions/; comma-separated names deploy a subset. Dependency order is controlled by .github/solutions-config.json.  |  Gate pattern: Each environment has a lightweight gate job (environment: declaration triggers approval) separate from the matrix deploy job — meaning ONE approval covers all N solutions.  |  Security scanning: BlackDuck SCA + Checkmarx SAST are enabled only when lowcode-nocode=true (individual toggles also apply). Solution Checker has no toggle — always mandatory.  |  Deployment settings: _reusable-deploy.yml resolves deployment-settings/{env}/{SolutionName}.json first, falls back to {env}/deployment-settings.json for backward compatibility.  |  Export: Sequential max-parallel:1 with git pull --rebase before each commit prevents conflicts on the shared branch. Single PR created after all exports.

Single-Solution Repo
repo/
├── src/solutions/
│   └── MySolution/            ← solution source
├── deployment-settings/
│   ├── dev/deployment-settings.json
│   ├── intg/deployment-settings.json

├── config/
│   └── data-schema.xml          ← optional
└── .github/

Multi-Solution Repo
repo/
├── src/solutions/
│   ├── CoreSolution/           ← deploy first
│   ├── ExtensionA/            ← depends on Core
│   └── ExtensionB/            ← depends on Core
├── deployment-settings/
│   ├── dev/
│   │   ├── CoreSolution.json
│   │   ├── ExtensionA.json
│   │   └── ExtensionB.json
│   └── prod/... (same pattern)
├── config/
│   ├── CoreSolution/data-schema.xml
│   └── ExtensionA/data-schema.xml
└── .github/
    ├── solutions-config.json  ← order!
    └── workflows/
Use solutions: "all" for full pipeline or
solutions: "CoreSolution, ExtensionA" for subset.
