Key Design Decisions
Multi-solution: All workflows accept a solutions input — "all" deploys every solution in src/solutions/; comma-separated names deploy a subset. Dependency order via .github/solutions-config.json.
Two-repo split: deploy-dev.yml and rollback.yml in GHA-Dynamics are thin wrappers. They read vars.* (inaccessible in reusable workflows) and delegate all logic to GHA-Core.
Artifact flow: Build → GHA artifact upload (solution-{name}-{run#}) → Deploy downloads from GHA. JFrog receives uploads in build and gets tagged after Prod — but is NOT the download source.
Solution backup: export-solution@v1 (not backup-environment@v1). Artifact: backup-{solution}-{env}-v{run#}. Rollback re-imports this ZIP via import-solution@v1.
Blocking check: Warn-only — pipeline never fails from async ops count. OAuth failure still fails fast (credential error).
Gate pattern: Lightweight gate job with environment: (no matrix) before each deploy matrix — ONE approval covers all N solutions.
🚀 Ad-hoc Dev Deploy — deploy-dev.yml → _reusable-deploy-dev.yml
Triggered manually (workflow_dispatch). Thin wrapper in GHA-Dynamics reads vars.* then delegates everything to _reusable-deploy-dev.yml in GHA-Core. Build and deploy patterns are identical to the release pipeline build and Dev deploy stages.
